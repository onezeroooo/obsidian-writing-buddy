# 墨伴 · Writing Buddy

写长篇用的 Obsidian 插件：就着选中的段落提问、生成改写、每一处改动先看清楚再落到正文。

[English](README.md) | 简体中文

墨伴把对话、写作工具和改动审阅放在正文旁边，改不改、改哪里始终是你说了算。任何改动都先摆出来再应用；
生成期间原文动过的，宁可拒绝也不覆盖；对话就是库里的普通文件。后端可以是自托管运行时、直连 API，
或者本机的模型服务。

## 功能

- 就着选中的段落提问，不动原文。
- 通过明确的写作动作生成改写候选，中文改动用**逐字级 diff** 看清楚再应用。
- 生成过程中选区变了就拒绝这次改动；已应用的改动只在目标区间仍然安全时才允许撤销。
- 对话、项目指令、自建技能都留在库里；随包分发的内置技能保持只读。
- 每个对话各自选上下文：Agent 自行判断的 **Auto**、要求全覆盖的 **Full**、只看本地的 **Low**。
- 可以配置多个自托管运行时 / 直连 API / 本地连接，按对话切换。

## 快速开始

需要 Obsidian 1.4.5 或更高。桌面端可用；移动端需要走自托管运行时或直连 API——Ollama 这类本地连接
默认服务在同一台机器上。

1. 在 Obsidian 里打开**设置 → 第三方插件 → 浏览**，搜索 **Writing Buddy**，点**安装**。
2. 在**第三方插件 → 已安装插件**里启用 **Writing Buddy**。
3. 到**设置 → 墨伴 → AI Connections** 添加一个连接（见下文「配置」）。

更新和其他插件一样，通过 Obsidian 的第三方插件机制送达。

## 配置

在**设置 → 墨伴 → AI Connections** 里添加连接。每个对话各自选连接、服务商、模型、思考强度和上下文。
设备本地的预设决定新对话用什么；这台设备一旦改过某个对话，那次选择会被记住，且不会同步到别的设备。

**上下文**是客户端自己的控制项，和模型的思考强度是两回事：

| | |
|---|---|
| **Auto** | 交给 Agent 判断——就地综合、用受控工具做检索，或者在正确性确实需要时请求全覆盖 |
| **Full** | 走全文工作流，完整覆盖当前稿件 |
| **Low** | 只看选区、它的上下文和当前编辑器里的文字，绝不跨文件检索 |

检索过程中由 Agent 决定下一步查什么，但**哪些库内容可用、实际去读、校验版本、预算与中断**全部由墨伴
自己把关。后端拿不到路径、拿不到文件系统能力，也直接碰不到你的库。

本地连接支持 Ollama 和 OpenAI 兼容的 llama.cpp 服务（默认 `http://127.0.0.1:8793/v1`，仅回环，
密钥可填可不填）。墨伴不会去启动或管理模型进程。

## 指令与技能

每一轮都组装成一份指令栈：不可改的产品策略、当前适用的内置规则、可选的
`WritingBuddy/instructions/project.md`，外加至多一个任务技能。项目指令和技能只能叠加——不能削弱策略、
不能获得编辑权限，也不能把正文内容变成命令。

八个内置技能随包分发，不会被写进你的库。在**设置 → 墨伴 → 指令与技能**里可以查看内置技能、保存一份
叠加的自定义、单独重置它，或者建一个完全属于你的技能。详见 [Writing skills](docs/SKILLS.md)。

## 隐私与联网

- 没有墨伴账号。AI 服务商或自托管运行时都由你自己配置，插件背后没有任何服务。
- 服务商可能需要你自己的账号、API 密钥、额度或付费，并各自有隐私与数据政策。直连 API 支持
  OpenAI、Anthropic、Google 以及任何 OpenAI 兼容端点。
- 发送一轮对话时，选中的正文、你的指令，以及插件在所选上下文模式和预算内从库里整理出的上下文，
  会发给这个对话选定的连接。除此之外不会发送任何内容。
- 本地连接（Ollama、回环地址上的 llama.cpp 服务）和自托管运行时让这些流量留在你自己的机器或网络里。
- API 密钥和运行时凭据只存在这台设备上，不会写进会同步的库文件。
- 墨伴没有遥测和分析，自身不会发起任何网络请求。
