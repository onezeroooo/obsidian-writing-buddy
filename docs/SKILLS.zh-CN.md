# 技能

[English](SKILLS.md) | 简体中文

一个技能对应一项写作任务。它不负责产品安全、来源处理、引用语法或改写输出的
封装格式；这些共享规则由墨伴在每一轮对话中单独组合。这样技能可以保持很小，
只描述作者想要做的事。

## 所有权模型

现行的技能分为三类：

| 类别 | 来源 | 可编辑？ | 升级时的行为 |
| --- | --- | --- | --- |
| 内置 | 插件包 | 否 | 随下一个插件版本整体替换 |
| 已自定义的内置 | 插件包中的基础版本加上 `WritingBuddy/skills/overrides/<id>.md` | 只能编辑作者自己叠加的部分 | 以最新的内置基础版本为准，再叠加作者的自定义 |
| 自建 | `WritingBuddy/skills/custom/<id>.md` | 是 | 与内置版本无关 |

全新安装不会向库中写入任何内置 Markdown。在 **设置 > 墨伴 > 指令与技能**
里，**查看内置** 以只读方式展示插件自带的任务指令；**编辑我的自定义** 只保存
作者叠加的附加要求；**重置自定义** 只删除这一条叠加，不会覆盖内置技能或其他
自建技能；**+ 新建技能** 打开结构化编辑器，用于创建自建技能。

现行目录布局：

```text
WritingBuddy/
├── instructions/
│   └── project.md                 可选的全书通用自定义
└── skills/
    ├── custom/
    │   └── <id>.md                自建技能
    ├── overrides/
    │   └── <builtin-id>.md        叠加式自定义；以及旧版的完整替换
    └── state/
        ├── migration.json         旧版文件的分类台账
        └── resets.json            独立的显式重置回执
```

直接放在 `WritingBuddy/skills/*.md` 的顶层文件只作为旧版来源看待，见
[旧版扁平文件迁移](#旧版扁平文件迁移)。

## 八个内置技能

`ask-selection` 不再是插件自带的技能，也不再作为自动回退。对所附段落提出普通
问题就是带有选区依据的普通对话，历史记录中不会出现凭空捏造的 `ask-selection`
身份。作者仍然可以用这个 id 明确拥有一个自建技能，包括从编辑过的旧版文件中
保留下来的那个。

| 技能 id | 名称 | 分类 | 动作 | 范围 |
| --- | --- | --- | --- | --- |
| `rewrite` | 改写 | 写作 | `rewrite` | 选区 |
| `polish` | 润色 | 写作 | `rewrite` | 选区 |
| `shorten` | 精简 | 写作 | `rewrite` | 选区 |
| `expand` | 扩写 | 写作 | `rewrite` | 选区 |
| `continue` | 续写 | 写作 | `continue` | 选区 |
| `scene-polish` | 场景打磨 | 写作 | `rewrite` | 选区 |
| `pacing` | 节奏诊断 | 审读 | `chat` | 选区 |
| `consistency` | 一致性检查 | 审读 | `chat` | 整个项目 |

`scene-polish` 吸收了 `show-not-tell`、`dialogue` 和 `transition`；它根据请求、
选区和上下文判断这一段真正需要哪一种处理，而不是每次全部跑一遍。
`consistency` 吸收了 `character-consistency`、`continuity` 和 `foreshadow`；它
以"证据比对"任务的形式交给 Agent，因此在自动模式下由 Agent 决定要研究哪些项目
材料，以及正确性是否需要走现有的全稿流程。这个判断依据语义覆盖标准，而不是
"技能对应来源"的配方或客户端关键词规则。`chapter-summary` 已退役且没有继任
者——总结一章是普通对话，不是任务技能。

旧的引用仍然可以加载：六个退役 id 会映射到接替它们的技能，`chapter-summary`
则降级为"无技能"。从库中加载的技能始终优先于这个映射，所以作者可以把退役 id
拿来用于自己的技能。

两个审读技能启用内置的审读行为：结论先行、证据可核对、不捏造发现、不给替换
文本。五个改写技能和 `continue` 使用内置的写作与输出契约。

## 生效的指令栈

墨伴在执行前会冻结一份指令栈，顺序如下：

1. 不可变的产品策略；
2. 适用的内置行为：选区依据、写作规则、审读规则、引用规则，以及改写或续写的
   输出契约；
3. 来自 `WritingBuddy/instructions/project.md` 的可选项目自定义；
4. 解析出的任务技能（如果有）。

产品层和共享层随代码发布，不能在库中编辑。项目和技能文本可以增加偏好，但不能
删除或凌驾于它们之上。当前请求以及仍然适用的作者约束和纠正属于作者指令。附上
的选区是指涉对象及其原文的权威证据，但它和其他稿件或检索材料一样只是引用的
证据，不是可执行的指令，附上本身也不赋予其正典地位。除非作者采纳，早先的助手
输出既不是作者指令也不是正典。模型的回复不能授权任何编辑，也只能引用客户端
提供的来源。

共享规则只存在一份。不要在每个技能正文里重复引用语法、选区依据、通用审读
行为或"只返回候选文本"之类的样板。这样可以避免每个技能都带着同一份协议的
副本，然后各自走样。

项目自定义是可选的，仅仅读取它不会创建文件。它的 Markdown 正文是叠加式的。
安全的 frontmatter 会在使用前剥离；格式错误的 frontmatter 或看起来像凭据的键
会让整个文件失效，而不是被当作指令。

## 结构化路由

每一轮都会记录一份可检视的路由结果：选中的技能或"无技能"、来源（`explicit`、
`inferred` 或 `none`）、原因，以及评估过的候选项。优先级为：

1. 在动作行中明确选择的技能；
2. 通过技能路由元数据匹配到的明确意图；
3. 无技能。

这不是简单的子串匹配。路由器会考虑动作类型、范围、声明的短语、祈使句或疑问句
的句式、对编辑的否定，以及是否存在选区。"不要改写，只解释为什么"和"为什么这里
要改写？"仍然是普通对话。仅限选区的动作在没有选区时不会运行。像"再克制一点"
这样简短而明确的祈使追问可以沿用上一轮的改写技能。如果多个候选同时存活，最长
的短语胜出，平局时按稳定的技能顺序决定。拉丁字母短语要求类似词边界的匹配；中
日韩短语使用自然包含。

自建技能通过 `routing` 元数据参与路由，因此不需要改代码。旧版的 `triggers` 作为
扁平文件的表示形式仍然接受。

## 自建技能格式

设置里的表单是首选的编写方式。生成的 Markdown 也刻意保持可读、可手动编辑：

```markdown
---
id: scene-tension
name: 场景张力检查
action: chat
scope: selection
version: 1
description: 找出张力松掉的位置。
composerPrompt: 帮我检查这一段的场景张力
routing: 检查张力、场景太平
routingAllowQuestions: true
instructionProfile: review
---

检查这一场景的目标、阻力和转折。
指出具体位置以及张力为何减弱。
```

frontmatter 是一种小而扁平的 `key: value` 格式。识别的字段有：

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| `schemaVersion` | 否 | 若存在，目前必须为 `1` |
| `id` | 否 | 默认取文件名；只允许单词字符和 `-` |
| `name` | 否 | 显示名称；默认为 `id` |
| `action` | 是 | `chat`、`rewrite` 或 `continue` |
| `scope` | 否 | `selection`（默认）、`current-document` 或 `project` |
| `version` | 否 | 正整数，默认 `1` |
| `description` | 否 | 技能列表中的简短描述 |
| `composerPrompt` | 否 | 填入输入框的人类可读请求 |
| `routing` | 否 | 用顿号或逗号分隔的语义触发短语 |
| `routingAllowQuestions` | 否 | `true` 允许从分析类的疑问句推断 |
| `instructionProfile` | 否 | 目前只支持 `review` |
| `mode` | 仅自定义文件 | `extend` 或 `replace` |
| `baseVersion` | 仅自定义文件 | 内置基础版本的正整数版本号 |
| `baseHash` | 仅自定义文件 | 内置基础版本的 64 位 SHA-256 |

未知的键会被忽略。已知字段会做校验；不支持的 schema 版本、动作、范围、自定义
模式、指令配置、布尔值或哈希都会被拒绝。Markdown 正文不能为空。

`action` 决定结果的形态：

- `chat` 产生回答，没有写入稿件的路径。
- `rewrite` 针对精确捕获的选区产生一个替换候选。
- `continue` 产生新的文字，插入到捕获的选区之后。

两种写作动作在作者按下 **应用** 且精确范围的新鲜度检查通过之前，都只是候选。
技能不能选择连接、提供方、模型、力度、文件路径、shell 命令、工具或权限级别。

## 内置技能的自定义

常规的内置自定义使用 `mode: extend`，并记录内置基础版本的 `baseVersion` 和
SHA-256 `baseHash`。它的正文会追加到最新的内置任务指令之后。由版本发布掌管的
名称、路由和任务语义会继续随升级推进，除非自定义明确提供了叠加的元数据值。

`mode: replace` 为了迁移兼容而保留。它保存的是一份旧的完整技能，其中用户的
修改无法与历史内置版本安全分离。当替换文件记录的基础哈希与当前内置基础不符
时，会被标记为 **需要复核**，但仍然可以被路由。新的自定义应当使用设置界面和
叠加模式。

## 旧版扁平文件迁移

每次重新加载时，`WritingBuddy/skills/` 下的每个顶层 Markdown 文件都会被分类，
依据是它的精确来源哈希、安全情况下的规范化表示、截至 0.4.1 随插件发布的内置
文件的冻结目录，以及解析出的技能 id。结果记录在
`WritingBuddy/skills/state/migration.json`。

| 旧版输入 | 分类 | 结果 |
| --- | --- | --- |
| 与已知随插件发布的默认文件完全一致，包括可识别的 BOM 或换行符变体 | `seeded-mirror` | 原地保留但不生效；当前内置版本生效 |
| 可解析的已修改文件，其 id 既是历史内置又是当前内置 | `legacy-customization` | 以 `mode: replace` 复制到 `skills/overrides/` 待复核；原文件保留 |
| 可解析且 id 为其他任意值的文件，包括被修改过的退役内置技能（如 `ask-selection`） | `legacy-custom` | 逐字节复制到 `skills/custom/`；原文件保留 |
| 格式错误的 Markdown | `malformed` | 原地保留、不生效，并在设置中报告 |
| 无关的非 Markdown 文件 | 不分类 | 不做任何处理 |

对于已移除的 `ask-selection` id，未改动的历史副本视为不生效的镜像；改动过的副本
是作者自己写的行为，会作为普通自建技能保留，但永远不会变成选区对话的自动回退。

迁移是幂等且尊重所有权的。台账记录来源路径和哈希，以及生成目标的哈希。再次
重新加载时，未改动的来源直接复用已有的分类结果，不会生成第二份副本。同步过来
的台账永远不授予覆盖权：如果一个被保留的来源发生了变化，而同一技能 id 已经有
了不同的、作者拥有的生效内容，墨伴会保留那份生效文件，不创建第二份生效的
重复项，只记录待处理的输出哈希，并报告该来源以供复核。别处已经存在的相同副本
会被复用。仅文件名冲突时会改用 `<stem>-legacy-<12 位哈希>.md`，必要时再加上
确定性的数字后缀。

清单条目会经过校验，而不是盲目信任。重置一个迁移而来的自定义文件时，会在
`skills/state/resets.json` 下单独写一份不透明回执，因此仅凭清单的重置声明不能
压制保留的来源；真正重置之后，未改动的来源会保持不生效。如果同步状态乱序到达，
只有当哈希与独立回执匹配时，才会移除精确对应的过期生成文件；作者改动过的自定
义文件会被保留。这是针对作者拥有的同步状态的防损坏措施，不是针对故意同时编辑
两份状态文件的所有者的密码学边界。迁移永远不会修改、移动或删除来源，也不会碰
无关文件。

## 错误、冲突与重新加载

有效的自定义和自建技能会在库文件变化时重新加载。同步写入一半的损坏文件会被
报告，同时该路径上一次有效的解析结果继续可用。重复的生效 id 是确定性的冲突：
两个候选都不参与路由，并且报告每一个冲突路径，而不是按文件系统的列举顺序取
一个。放错所有权目录的文件同样会被报告，而不是被悄悄提升。

## 版本升级契约

- 内置技能和产品策略随插件包更新。
- 叠加式自定义会重新应用到最新的内置基础之上。
- 旧版的完整替换会被保留；当记录的基础版本不同时可能被标记为 **需要复核**。
  目前没有静默的三方合并。
- 自建技能、旧版来源文件和迁移台账都会保留。
- 重置只移除所选内置技能上作者自己的自定义。没有全局"恢复内置"操作，也不会
  覆盖用户文件。

## 记忆边界

`WritingBuddy/memory/*.md` 目前只包含手工整理的笔记。这些笔记可以作为低优先级
的只读证据被选中，但墨伴不会创建持久记忆、提议、修订、过期记录或向量索引。
自动记忆捕获和技能演化仍属于未来的设计工作。
